Question 1: Frontend vs Backend vs Full-Stack Development
Frontend Development
Frontend development refers to building the part of a website or application that users directly see and interact with in their browser — the layout, design, buttons, forms, and animations. It is built primarily using HTML (structure), CSS (styling), and JavaScript (interactivity), often with frameworks such as React, Angular, or Vue.js.
Real-world example: The visual design and interactive elements of Netflix's homepage — the movie thumbnails, hover animations, search bar, and navigation menu — are all built by frontend developers.
Backend Development
Backend development refers to the server-side logic that powers an application: processing requests, running business logic, managing authentication, and communicating with databases. Common backend languages/frameworks include Node.js, Python (Django/Flask), Java (Spring), PHP, and Ruby on Rails.
Real-world example: When a user logs into Amazon, the backend verifies the username and password against the database, checks the order history, and calculates prices and discounts before sending the result back to the frontend.
Full-Stack Development
A full-stack developer works on both the frontend and backend of an application, understanding how the client-side and server-side communicate and integrate with databases. They can build a complete, working application end-to-end.
Real-world example: A solo developer building a food-delivery app from scratch — designing the ordering screen (frontend), writing the order-processing and payment logic (backend), and managing the restaurant/menu database — is working as a full-stack developer.

Question 3: How a Browser Requests and Displays a Web Page
When a user types a URL into a browser and presses Enter, a sequence of steps takes place:
    • 1. DNS Resolution — The browser first performs a DNS lookup to convert the human-readable domain name (e.g. www.example.com) into an IP address.
    • 2. Establishing a Connection — The browser opens a TCP connection with the server at that IP address (and performs a TLS handshake if the site uses HTTPS).
    • 3. Sending the HTTP Request — The browser sends an HTTP/HTTPS request (typically a GET request) asking for the specific page or resource.
    • 4. Server Processing — The web server receives the request, processes it (possibly querying a database or running backend logic), and sends back an HTTP response containing the HTML document and a status code (e.g. 200 OK).
    • 5. Parsing the Response — The browser parses the HTML to build the DOM (Document Object Model), fetches linked resources such as CSS and JavaScript files, and applies styling to build the CSSOM.
    • 6. Rendering the Page — The browser combines the DOM and CSSOM into a render tree, calculates layout, and paints pixels on the screen. JavaScript is executed to add interactivity.
    • 7. Display & Ongoing Requests — The completed page is displayed to the user, and further requests (e.g. for images, fonts, or AJAX data) continue in the background as needed.

Question 5: What is a Web Server?
A web server is software (often running on dedicated hardware) that stores, processes, and delivers web pages and other content to clients over the internet using the HTTP/HTTPS protocol. When a browser requests a resource, the web server locates or generates that resource and sends it back as an HTTP response.
Commonly Used Web Servers
    • Apache HTTP Server — An open-source web server known for its flexibility and wide use with PHP-based sites (e.g. WordPress).
    • Nginx — A high-performance web server and reverse proxy known for handling large numbers of concurrent connections efficiently; commonly used for high-traffic sites.
    • Microsoft IIS (Internet Information Services) — Microsoft's web server, tightly integrated with the Windows and .NET ecosystem.
    • Node.js (Express) — A lightweight web server commonly bundled with Node.js applications, often used with the Express.js framework.
    • LiteSpeed — A web server developed by the Apache Software Foundation, focused on performance and modern protocols like HTTP/2 and HTTP/3.

Question 7: Installing and Configuring VS Code
Below are the steps to install and configure Visual Studio Code for HTML, CSS, and JavaScript development:
    • 1. Download — Go to the official website at code.visualstudio.com and download the installer for your operating system (Windows, macOS, or Linux).
    • 2. Install — Run the installer and follow the setup wizard. On Windows, it is recommended to check "Add to PATH" during installation.
    • 3. Install Extensions — Open VS Code, go to the Extensions panel (Ctrl+Shift+X), and install useful extensions such as Live Server (to preview HTML pages with auto-reload), Prettier (code formatter), ESLint (JavaScript linting), and HTML/CSS/JS IntelliSense.
    • 4. Set Up a Project Folder — Create a new folder for the project, open it in VS Code (File > Open Folder), and create index.html, style.css, and script.js files to begin coding.
    • 5. Test the Setup — Right-click index.html and select "Open with Live Server" to view the page in the browser with automatic reloading whenever a file is saved.

Question 9: Five Web Browsers and Their Rendering Engines
Browser	Developer	Rendering Engine
Google Chrome	Google	Blink (with V8 JavaScript engine)
Mozilla Firefox	Mozilla Foundation	Gecko (with SpiderMonkey JavaScript engine)
Safari	Apple	WebKit (with JavaScriptCore engine)
Microsoft Edge	Microsoft	Blink (Chromium-based, with V8 engine)
Opera	Opera Software	Blink (Chromium-based, with V8 engine)

Rendering engines are responsible for parsing HTML/CSS and painting content on screen. Blink (used by Chrome, Edge, and Opera) is derived from WebKit and is known for speed and broad web-standards support. Gecko (Firefox) is an independent engine developed by Mozilla, valued for strong standards compliance and privacy features. WebKit (Safari) is optimized for Apple devices and known for power efficiency. Because different engines can interpret certain CSS or JavaScript features slightly differently, developers test websites across multiple browsers to ensure consistent cross-browser compatibility.
